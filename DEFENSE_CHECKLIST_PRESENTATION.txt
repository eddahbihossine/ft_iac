ft_IaC — Defense / Evaluation Checklist Presentation Script

How to use this file
- This is a “talk track” + “demo script” aligned to the official checklist.
- For each item: say WHAT it is, show WHERE it is in the repo, and demo HOW it works.

0) Preliminary rules (evaluator)
- Defense only with student/group present (knowledge sharing).
- If repository is missing required files or wrong structure → stop (grade 0).
- Evaluator clones the repo on their machine and deploys from scratch.

1) General decisions (IaC tool + Cloud provider)
- IaC tool used: Terraform
  - Location: terraform/*.tf
  - Why Terraform: declarative, reproducible, supports AWS primitives (VPC/ALB/ASG/RDS/Route53/ACM/CloudFront).
- Cloud provider used: AWS
  - Why AWS: broad service coverage, clean HA primitives (ALB/ASG), Route53/ACM integration, managed RDS, CloudWatch/SNS for alerting.
- Deployment “pipeline platform”
  - This project uses an interactive deploy CLI instead of CI: scripts/deploy.js
  - Why: lets an evaluator deploy without student intervention (region selection, workspace naming, tfvars generation, safe retry/adopt flows).

2) Cloud infrastructure (mandatory)

2.1 Distributed application / Multiple servers (mandatory)
- Requirement: app must run on at least 2 separate servers (HA).
- Evidence (repo)
  - ASG + Launch Template: terraform/asg.tf
  - Minimum enforced when enable_alb=true: terraform/variables.tf (checks)
- Demo
  1) In AWS console: EC2 → Auto Scaling Groups → verify Desired/Min >= 2.
  2) Show at least two InService instances.

2.2 “Which server handled my page?” (mandatory)
- Requirement: the user can identify which server served the page.
- Evidence (repo)
  - Nginx injects a banner containing $hostname and $server_addr:
    - terraform/asg.tf (user_data → /etc/nginx/conf.d/app.conf)
  - Why this is legitimate: improvement for cloud compatibility; no fake info, the banner is generated by Nginx from real host data.
- Demo
  1) Open the app URL.
  2) Scroll to page bottom: banner shows server hostname.
  3) Open an Incognito window (new ALB cookie) and refresh; you can often observe a different hostname.

2.3 Preserving authentication on refresh (mandatory)
- Requirement: user remains logged in after multiple refreshes.
- Evidence (repo)
  - App stores logged-in user in session: src/login/login.controller.ts
  - Session middleware: src/main.ts
  - Session persistence across instances: MySQL-backed session store via express-mysql-session (shared DB)
- Demo
  1) Login.
  2) Refresh 10+ times: still logged in.
  3) (Optional stronger test) Open a second browser profile and login: both remain authenticated.

2.4 Shared data (mandatory)
- Requirement: data created on one instance is visible from another instance quickly.
- Evidence (repo)
  - Shared persistence uses MySQL:
    - App uses TypeORM MySQL: src/app.module.ts
    - HA mode uses RDS MySQL: terraform/database.tf
  - App data is stored in DB (Todo/User entities): src/todos/entities/todo.entity.ts, src/users/entities/user.entity.ts
- Demo
  1) Create a todo.
  2) Open another browser profile (likely different instance per banner) → todo is visible immediately.

2.5 High availability (mandatory)
- Requirement: app stays available after deleting an instance; recovers after deleting all.
- Evidence (repo)
  - ALB health checks + ASG health_check_type=ELB: terraform/asg.tf and terraform/alb.tf
  - Rolling instance refresh configured: terraform/asg.tf
- Demo
  1) Terminate one EC2 instance in the ASG.
  2) App stays reachable (other target still healthy).
  3) ASG launches a replacement instance.
  4) (Optional) Terminate all instances: ASG recreates and ALB becomes healthy again.

2.6 Scalability (mandatory)
- Requirement: scale out when CPU/RAM load is too high.
- Evidence (repo)
  - Target tracking autoscaling policy (CPU 60%): terraform/asg.tf (aws_autoscaling_policy.cpu_target)
- Demo (simple)
  1) Use a load tool from a machine you control (hey/wrk) against the app endpoint.
  2) Show CloudWatch ASG metrics rising.
  3) Show ASG increasing desired capacity.

2.7 Cost management (mandatory)
- Requirement: instance/DB sizes are reasonable + dev cost-minimizing config exists.
- Evidence (repo)
  - Friendly sizing knobs: terraform/locals.tf (small/medium/large mappings)
  - Cost profile toggle: terraform/variables.tf (cost_profile free vs standard)
- Demo
  1) Show cost_profile="free" disables ALB/CloudFront/RDS.
  2) Show cost_profile="standard" enables full HA stack.

2.8 Security (mandatory)
- Requirement: DB not public; no repo secrets; no plaintext secrets in provider console startup script.
- Evidence (repo)
  - RDS is private: publicly_accessible=false: terraform/database.tf
  - DB SG allows only app SG: terraform/database.tf
  - DB password is AWS-managed (Secrets Manager): terraform/database.tf (manage_master_user_password=true)
  - Instances read secret at runtime via IAM role policy: terraform/asg.tf
  - State / artifacts are gitignored and should not be committed: .gitignore
- Demo
  1) In RDS console: verify “Public access: No”.
  2) Show no secrets committed (no terraform.tfstate*, no .env*).

2.9 Alerts / Monitoring (mandatory)
- Requirement: admin gets alerted if app unhealthy / 5XX.
- Evidence (repo)
  - SNS topic + email subscription + CloudWatch alarms: terraform/alerts.tf
- Demo
  1) Provide alert_email in config.
  2) Confirm SNS subscription email.
  3) Trigger alarm (e.g., stop all targets briefly) and show email alert.

3) Infrastructure as Code (mandatory)

3.1 Modularity
- Requirement: not all code in one file; reusable logical blocks.
- Evidence (repo)
  - Terraform split by concern: terraform/vpc.tf, terraform/alb.tf, terraform/asg.tf, terraform/database.tf, terraform/alerts.tf, terraform/cloudfront.tf, terraform/acm_and_dns.tf

3.2 Region selection (friendly)
- Requirement: use simple names (EU/Paris) not only eu-west-3.
- Evidence (repo)
  - Map in terraform/locals.tf (region_map)
  - Deploy CLI reads that map: scripts/deploy.js

3.3 Selecting server & DB capacity (friendly)
- Requirement: small/medium/large selection.
- Evidence (repo)
  - terraform/locals.tf (server_instance_type_by_size + db_instance_class_by_size)

3.4 Re-configurable centralized static values
- Requirement: central place to modify values; redeploy updates infra.
- Evidence (repo)
  - terraform/locals.tf and terraform/variables.tf centralize mappings and overrides.
  - Changing e.g. server_instance_type_by_size or db_instance_class_by_size changes infra after apply.

4) Documentation & accessibility (mandatory)

4.1 Diagram present
- Requirement: at least one diagram describing infra.
- Evidence (repo)
  - docs/ARCHITECTURE_DIAGRAM.md (Mermaid diagram)

4.2 Accessible deployment
- Requirement: evaluator can deploy without student intervention.
- Evidence (repo)
  - Root README explains: README.md
  - Interactive deploy CLI: scripts/deploy.js
- Demo
  1) On a clean machine: corepack enable && pnpm i
  2) Run: pnpm deploy
  3) Script creates workspace + tfvars and runs init/plan/apply.

5) Cheat checks (mandatory)

5.1 No external Terraform modules
- Requirement: no prefabricated Terraform modules from registry/GitHub.
- Evidence
  - No module blocks in terraform/*.tf; only native resources.

5.2 No orchestrator managing a cluster
- Requirement: no Kubernetes/Nomad.
- Evidence
  - Infra uses EC2 + ALB + ASG; Docker Compose is used only locally per instance (allowed).

5.3 No PaaS usage
- Requirement: do not run app on PaaS (Beanstalk/ECS/Fargate/AppRunner/etc.).
- Evidence
  - Infra is IaaS style: EC2 + ALB + ASG; DB is RDS (managed DB is allowed by the project statement).

5.4 No malicious modified application
- Requirement: app not altered to mislead evaluator.
- Evidence
  - Server-ID banner shows real Nginx $hostname and $server_addr (not hard-coded).

Suggested live defense flow (10–15 minutes)
1) Show diagram (docs/ARCHITECTURE_DIAGRAM.md)
2) Show deploy command: pnpm deploy
3) Show multiple instances + banner proof
4) Login + refresh
5) Create todo in one browser, see it from another
6) Terminate instance, show continued availability + replacement
7) Show autoscaling policy + how to test
8) Show security posture + alerts.tf

Common Q&A answers (short)
- Why AWS? Tight integration ALB/ASG/ACM/Route53 + managed RDS.
- Why Terraform? Reproducible infra, easy toggles per environment.
- How is auth preserved? Express sessions stored in MySQL so any instance can validate.
- How is shared data done? Central MySQL (RDS) used by all app instances.
- How is HA guaranteed? ASG min=2 + ALB health checks + automatic replacement.
- How is scaling done? TargetTrackingScaling on ASGAverageCPUUtilization.
