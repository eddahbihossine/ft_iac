Terraform Learning Map

This page explains your Terraform project in the exact order Terraform thinks. Learn it like a story: what gets loaded first, what depends on what, and what appears in AWS at the end.

Terraform does not run files top-to-bottom. It reads all .tf files together, builds a dependency graph, then executes resources in dependency order.

1) What Happens First to Last

1

Load and Parse Configuration

Terraform reads every file in terraform/ and merges them into one configuration.

2

Check Inputs and Rules

Variables from terraform.tfvars are loaded, then the check "tls_dns_inputs" rule validates DNS/TLS input consistency.

3

Initialize Providers

Providers from providers.tf are prepared: AWS main region and AWS us-east-1 alias for CloudFront certificates.

4

Build Dependency Graph

Terraform detects links like aws_subnet.public depends on aws_vpc.main, and listeners depend on ALB.

5

Plan

Terraform compares current state and AWS real resources, then prints create/update/destroy actions.

6

Apply in Order

Foundations first (VPC, subnets, security groups), then compute/ALB, then optional DNS/TLS/CloudFront, then outputs.

2) Project File Roles

variables.tf - input knobs and guardrails

Defines values you can change: region, subnet ranges, SSH key paths, domain settings, CloudFront toggle, and naming overrides.

inputs validation
providers.tf - AWS login + EC2 + app deploy

Declares providers, IAM role/profile, key pair, security groups, EC2 instance, then copies app files and runs Docker deploy commands via SSH.

provider ec2 provisioner
vpc.tf - network foundation

Creates VPC, internet gateway, public subnets, route table, and associations.

network
alb.tf - traffic entry point

Creates ALB, target group, listeners, and attaches EC2 to receive app traffic.

load-balancer
acm_and_dns.tf - ALB certificate and Route53 alias

When domain+zone are provided (and CloudFront is off), it requests ACM cert, validates DNS, and creates Route53 A record.

tls dns
cloudfront.tf - optional CDN and HTTPS edge

If enabled, creates CloudFront in front of ALB. Uses default CloudFront certificate without a custom domain, or us-east-1 ACM cert with domain.

cdn https
outputs.tf - final values shown to you

Prints ALB DNS/ARN, route53 record, certificate ARN, and final HTTPS endpoint.

result

3) Line-by-Line Compile Map (Exact File Ranges)

providers.tf (main engine)
  • 1-13: Terraform + provider requirements are read first so Terraform knows what plugins are needed.
  • 15-29: locals.app_deploy_hash is computed from app files; this decides if deploy steps should re-run.
  • 31-35: Primary AWS provider config (region/profile).
  • 38-43: Secondary provider alias in us-east-1 for CloudFront-related ACM certificates.
  • 45-65: IAM role, policy attachment, and instance profile (permissions for EC2/SSM).
  • 67-70: EC2 key pair from your local SSH public key.
  • 72-144: Security groups (ALB and EC2 firewall rules).
  • 146-185: EC2 instance creation + startup script (Docker install, compose install, swap setup).
  • 187-270: Post-instance deploy actions: SSH, copy files, run docker compose, health check.
  • 272-274: EC2 public IP output.
variables.tf (inputs Terraform loads before graph)
  • 1-67: Declares all configurable inputs: region, ssh paths, network ranges, domain values.
  • 69-80: Safety check: domain and hosted zone must be both empty or both filled.
  • 82-98: Optional toggles/names (enable_cloudfront, ALB and TG custom names).
vpc.tf (network base; almost everything depends on this)
  • 1-8: VPC creation.
  • 10-13: Internet gateway attached to VPC.
  • 15-24: Public subnets across AZs.
  • 26: Reads available AZs data source.
  • 28-41: Public route table and subnet associations.
  • 43-49: Network outputs.
alb.tf (traffic control)
  • 1-8: ALB resource.
  • 10-25: Target group + health check path /health/liveness.
  • 27-36: HTTP listener (only when redirect mode is not used).
  • 38-53: HTTP to HTTPS redirect listener when custom domain mode is active.
  • 55-67: HTTPS listener with ACM certificate for ALB mode.
  • 69-73: Attach EC2 instance to target group.
  • 75-77: Final app URL output logic.
acm_and_dns.tf (ALB TLS + Route53)
  • 1-9: ACM cert for ALB path (disabled when CloudFront mode is on).
  • 11-18: DNS validation records for cert.
  • 20-24: Certificate validation completion resource.
  • 26-36: Route53 alias A record to ALB or CloudFront depending on mode.
cloudfront.tf (optional CDN + HTTPS edge)
  • 1-28: Optional us-east-1 cert + DNS validation for custom domain CloudFront.
  • 30-79: CloudFront distribution itself (origin ALB, cache behavior, TLS settings).
  • 81-83: CloudFront domain output.
outputs.tf (final exported values)
  • 1-7: ALB DNS and ARN.
  • 9-11: Route53 record fqdn if created.
  • 13-15: Certificate ARN selected by mode.
  • 17-19: HTTPS endpoint selected by mode.

4) Real Execution Order in This Stack

Simple dependency chain (happy path):

Variables -> Providers -> VPC/IGW/Subnets -> Security Groups -> IAM + KeyPair -> EC2 -> Target Group -> ALB -> Listener(s) -> Optional ACM/DNS/CloudFront -> Outputs

5) How to Read Plan Like a Pro

+ create: Terraform will make something new.

~ update: Terraform will change an existing resource.

- destroy: Terraform will remove a resource.

-/+: Terraform must replace the resource (destroy then recreate).

Tip: each time you edit variables, run terraform plan first and read this page while matching each resource to its file.
